# 动作数据采集规范

本目录用于保存 ESP32-S3 + MPU6050 动作识别原型的训练与验证数据。采集脚本只读取串口，不会给开发板发送命令，也不会主动复位硬件。

## 使用方法

先关闭 PuTTY、Arduino 串口监视器等会占用 COM7 的程序，然后在项目根目录运行：

```powershell
python tools/capture_motion.py --port COM7 --label chin_tuck --seconds 15 --subject S01
```

如需指定输出目录：

```powershell
python tools/capture_motion.py --port COM7 --label still --seconds 20 --subject S01 --output data/raw
```

每个 CSV 都包含 `subject`、`label`、采集时间、串口、设备时间戳、六轴 IMU、姿态以及压力原值、滤波值、基线、增量和状态。脚本也兼容旧版仅 IMU 的 12 列固件。按 `Ctrl+C` 提前结束也会保存已经收到的数据。

## 通用采集要求

- 把传感器牢固固定在最终计划使用的位置，整批数据保持安装方向一致，不能让模块在衣服内晃动。
- 每位受试者、每个标签建议采集 **6–10 轮**；动作类每轮 10–20 秒，静止类每轮 20–30 秒。
- 建议至少采集 3–5 位身高、体型和动作习惯不同的人。训练集和验证集应按受试者划分，不能把同一个人的相邻片段随机拆到两边。
- 每轮只使用一个标签。动作幅度和速度要有自然变化，但不要在一轮中混入别的标签动作。
- 动作类每轮可重复 4–8 次；两次动作之间自然回到中立姿势，不要故意做得像机器人。
- 正样本 `chin_tuck` 很重要，但各种相似动作的负样本同样重要。数据量应尽量均衡，尤其不能只采少量 `look_down`、`nod`、`phone`。
- 记录异常情况，例如传感器松动、撞线、受试者做错动作；这类文件应重采，不要直接进入训练集。

## 标签定义

| 标签 | 标准动作与采集要点 |
| --- | --- |
| `chin_tuck` | 头颈保持基本竖直，下巴水平向后收，形成轻微“双下巴”，停 1–2 秒后回到中立位。不要同时明显低头。每轮混合轻/中等幅度和不同速度。 |
| `look_down` | 颈部向前屈，视线从前方转向下方；强调“低头”而非水平收下巴。采集不同低头角度，并自然回正。 |
| `look_up` | 颈部后伸、视线上移，再回到中立位。采集小幅和中等幅度，避免做到不舒服的极限角度。 |
| `nod` | 连续点头，由低头和回正构成，通常比单次 `look_down` 更快且重复。采集慢点头、正常点头和幅度变化。 |
| `turn_left_right` | 保持头部大致水平，绕竖直轴向左/右转头。每轮左右方向都要覆盖，也可补充只向单侧的轮次。 |
| `shrug` | 头部尽量保持中立，单肩或双肩上提再放松。传感器若在衣物/肩颈处，这一负样本尤其要多采。 |
| `walk` | 正常步行并保持自然看前方，覆盖起步、匀速、转弯和停止产生的震动；不要刻意收下巴。 |
| `drink` | 自然拿起杯子、靠近嘴部、轻微仰头或低头、喝水后放下。覆盖不同杯子和左右手，避免只录理想动作。 |
| `phone` | 坐姿或站姿看手机、滑动和打字，包含常见的持续低头与小幅姿势变化。这是 `chin_tuck` 的关键易混淆负样本。 |
| `posture_adjust` | 正常坐姿调整，例如身体前后移动、挺直、靠回椅背、转身取物或整理衣服；不要主动执行目标动作。 |
| `still` | 正常坐着或站着保持中立，可有呼吸和很小的自然晃动，但不做上述动作。不同坐姿、站姿分别采多轮。 |

## 推荐采集顺序

1. 先采 `still`、`chin_tuck`、`look_down`、`nod`，快速检查波形是否能区分。
2. 再完成 `look_up`、`turn_left_right`、`shrug`。
3. 最后采集 `walk`、`drink`、`phone`、`posture_adjust` 等真实场景负样本。
4. 第一版模型训练后，专门追加模型最容易误判的动作，形成“难负样本”迭代集。

不要把当前原型的输出当作医疗结论；本数据仅用于黑客松动作识别验证。
