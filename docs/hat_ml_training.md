# 帽子动作模型：真实训练与上线门槛

这份文档定义 Pecky Cap 的动作模型如何训练、验证和进入固件。目标不是做一个看起来“很智能”的模型，而是只让达到真实准确率门槛的模型进入 ESP32。

## 当前采用的模型

使用轻量监督式 TinyML，而不是强化学习或“智能体”。原因很简单：现有数据已经有类别标签，设备必须离线、低延时地判定动作；强化学习需要在线奖励与大量安全探索，不适用于穿戴式颈部训练计数。

模型输入是最近 2 秒、25 Hz 的七通道数据：先从每次上电的中立重力构建人体相对坐标，再投影三轴加速度、三轴角速度和相对压力。模型结构为：

```text
50 x 7 输入
→ Conv1D(7→12, kernel=5)
→ Depthwise Conv1D(12, kernel=5) + Pointwise Conv1D(12→16)
→ 全局平均池化
→ Dense(16→4)
→ background / 后仰 / 收下巴 / 后脑抗阻
```

该模型约 1,200 个参数；通过质量门槛后可量化为 int8 并放进 ESP32-S3。识别固件还必须加状态机：动作候选 → 连续高置信窗口 → 回到中立 → 1.5 秒冷却，才计一次，避免一次长时间保持被重复计数。

## 当前数据的真实限制

`hat_XXXX.csv` 的 `phase` 是按秒表自动写入的阶段，不是每次动作的精确开始/结束标签。一段 12 秒动作阶段里包含 3 次动作以及中间的休息。因此它可用于训练 V0 模型和定位问题，但不能把当前得分包装成最终“准确动作识别”。

压力传感器也被作为特征保留，但现有样本中只有部分参与者在抗阻阶段有稳定压力变化；在固定压力片位置前，压力不能作为所有人的强制判定条件。

空间坐标只能消除一部分佩戴角度偏差。它仍依赖“PCB 的 Y 轴始终固定为人体左右方向”；重力只能给出上下，不能自动知道前后。帽内模块若旋转或翻面，前后/左右特征都会失真，因此最终必须用内托或外壳固定模块方向。

## 固定的参与者级划分

不能随机拆分同一人的重叠窗口。默认划分为：

| 数据用途 | 参与者文件 |
| --- | --- |
| 训练 | `hat_0009`–`0011`、`hat_0016`–`0020`、`hat_0022`–`0026`（13 人） |
| 验证 | `hat_0027`–`0029`（3 人） |
| 最终测试 | `hat_0030`–`0031`（2 人） |

这样验证集代表模型面对从未见过的佩戴者，而不是记住同一个人的帽子角度和动作速度。

## 训练命令

在 WSL 项目根目录执行：

```bash
python3 tools/train_hat_motion_model.py
```

只做空间特征、特征族消融和数据质量诊断时执行：

```bash
python3 tools/analyze_hat_spatial_features.py
```

该命令使用参与者分组交叉验证，且继续封存 `hat_0030`、`hat_0031` 最终测试集。报告写到本地忽略目录 `models/hat_motion_v0/spatial_feature_report.json`。

训练产物只写入本地、Git 已忽略的 `models/hat_motion_v0/`：

- `quality_report.json`：训练/验证/测试真实指标；
- `model.pt` 和 `model_weights.npz`：本地模型权重；
- 仅当达到质量门槛时生成 `model_generated.h`，供后续固件量化/集成。

若想让命令在未达标时明确返回失败码，使用：

```bash
python3 tools/train_hat_motion_model.py --enforce-quality-gate
```

## 上线门槛

按当前产品目标，验证集必须同时满足：

| 验收项 | 指标 | 最低值 |
| --- | --- | ---: |
| 总体 | 从未见过的参与者的**平衡准确率** | 50% |
| 后仰脖子 | `neck_extension` F1 | 60% |
| 收下巴 | `chin_tuck` F1 | 60% |
| 双手抱头抗阻 | `head_resistance` 精确率 | 80% |
| 双手抱头抗阻 | `head_resistance` 召回率 | 80% |

抗阻不采用“二分类普通准确率”：背景窗口很多时，即使模型从不触发抗阻，普通准确率也可能很高。它必须同时有 80% 精确率（不乱报）和 80% 召回率（不漏报），才算真正满足“按压 + 运动 + 持续时间”的产品要求。

未达任一门槛时，脚本仍会保存模型和报告，便于诊断，但会标记为 `BLOCKED_NEEDS_CLEANER_LABELS_AND_HARD_NEGATIVES`，不会生成可用的固件模型头文件。

## 2026-08-29 当前训练结果（真实，不作为上线模型）

原始传感器轴 V0 在验证集上的普通准确率为 **37.01%**、平衡准确率为 **38.45%**、宏平均 F1 为 **37.23%**；封存测试者上的普通准确率为 **24.27%**、平衡准确率为 **26.78%**。加入中立重力人体坐标后再次训练，验证普通准确率为 **32.54%**、平衡准确率为 **34.81%**、宏平均 F1 为 **31.06%**；说明坐标变换本身不能修复粗标签与压力失效。

空间特征族在 16 位开发参与者上的分组交叉验证显示：后仰最好的是姿态+角速度，AUROC **0.677**、F1@0.5 **0.384**；收下巴全部 IMU 特征 AUROC **0.630**、F1@0.5 **0.386**；抗阻的压力单独 AUROC 只有 **0.451**、F1@0.5 **0.182**。抗阻结果异常不是压力无用，而是 18 份会话中只有 `0009/0010/0011/0018` 在 phase 5 有可靠压力，其余 14 份相应阶段压力为零。

因此本次训练结果被质量闸门正确拦截，**不得部署或声称已达到 50%/60%/80% 门槛**。这不是把模型做得不够大：当前标注把动作和休息混在同一类，且没有足够的困难负样本；更深的网络、强化学习或智能体只会更容易记住参与者与时间安排，而不会变得更可靠。详细物理解释见 `docs/spatial-feature-analysis.md`。

## 达标所需的下一轮数据

现有阶段标签不足以支撑可靠的三动作识别。下一轮必须保留同一顶帽、同一固定方式，并补齐：

1. 每个动作的每一轮用手机视频或明确的 LED/蜂鸣提示标记开始和结束；每人每类至少 6 次真实动作。
2. 每位参与者先检查后脑压力片是否有稳定变化，再采抗阻；无接触的样本不能被误标为抗阻。
3. 对每位参与者采集等量或更多的困难负样本：低头、点头、转头、耸肩、走路、看手机、喝水和正常坐姿调整。
4. 至少新增 10–15 位参与者；新增受试者仍保留为独立验证/最终测试，不能全放进训练集。

在数据达标前，演示版本可以运行本地状态机和采集/蓝牙链路，但不得宣称它已经通过 70% 的独立人群验证。
