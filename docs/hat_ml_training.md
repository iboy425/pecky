# 帽子动作模型：真实训练与上线门槛

这份文档定义 Pecky Cap 的动作模型如何训练、验证和进入固件。目标不是做一个看起来“很智能”的模型，而是只让达到真实准确率门槛的模型进入 ESP32。

## 当前采用的模型

使用轻量监督式 TinyML，而不是强化学习或“智能体”。原因很简单：现有数据已经有类别标签，设备必须离线、低延时地判定动作；强化学习需要在线奖励与大量安全探索，不适用于穿戴式颈部训练计数。

模型输入是最近 2 秒、25 Hz 的七通道数据：校准后的三轴加速度、三轴角速度和相对压力。模型结构为：

```text
50 x 7 输入
→ Conv1D(7→12, kernel=5)
→ Depthwise Conv1D(12, kernel=5) + Pointwise Conv1D(12→16)
→ 全局平均池化
→ Dense(16→4)
→ background / 后仰 / 收下巴 / 后脑抗阻
```

该模型约 1,200 个参数；通过质量门槛后可量化为 int8 并放进 ESP32-S3。识别固件还必须加状态机：动作候选 → 连续高置信窗口 → 回到中立 → 1.5 秒冷却，才计一次，避免一次长时间保持被重复计数。

## 当前数据的真实限制

`hat_XXXX.csv` 的 `phase` 是按秒表自动写入的阶段，不是每次动作的精确开始/结束标签。一段 12 秒动作阶段里包含 3 次动作以及中间的休息。因此它可用于训练 V0 模型和定位问题，但不能把当前得分包装成最终“准确动作识别”。

压力传感器也被作为特征保留，但现有样本中只有部分参与者在抗阻阶段有稳定压力变化；在固定压力片位置前，压力不能作为所有人的强制判定条件。

## 固定的参与者级划分

不能随机拆分同一人的重叠窗口。默认划分为：

| 数据用途 | 参与者文件 |
| --- | --- |
| 训练 | `hat_0009`–`0011`、`hat_0016`–`0020`、`hat_0022`–`0026`（13 人） |
| 验证 | `hat_0027`–`0029`（3 人） |
| 最终测试 | `hat_0030`–`0031`（2 人） |

这样验证集代表模型面对从未见过的佩戴者，而不是记住同一个人的帽子角度和动作速度。

## 训练命令

在 WSL 项目根目录执行：

```bash
python3 tools/train_hat_motion_model.py
```

训练产物只写入本地、Git 已忽略的 `models/hat_motion_v0/`：

- `quality_report.json`：训练/验证/测试真实指标；
- `model.pt` 和 `model_weights.npz`：本地模型权重；
- 仅当达到质量门槛时生成 `model_generated.h`，供后续固件量化/集成。

若想让命令在未达标时明确返回失败码，使用：

```bash
python3 tools/train_hat_motion_model.py --enforce-quality-gate
```

## 上线门槛

**验证集的参与者独立平衡准确率必须不低于 70%。** 平衡准确率比普通准确率更严格：它不会因为“背景”窗口较多而虚高。

未达 70% 时，脚本仍会保存模型和报告，便于诊断，但会标记为 `BLOCKED_NEEDS_CLEANER_LABELS_AND_HARD_NEGATIVES`，不会生成可用的固件模型头文件。

## 2026-08-28 当前训练结果（真实，不作为上线模型）

已用当前 18 份完整协议数据按上述 13/3/2 参与者划分训练一次。V0 TinyDepthwiseCnn 在验证集上的普通准确率为 **37.01%**、平衡准确率为 **38.45%**、宏平均 F1 为 **37.23%**；最后两位从未参与训练或调参的测试者上，普通准确率为 **24.27%**、平衡准确率为 **26.78%**。

因此本次训练结果被质量闸门正确拦截，**不得部署或声称已达到 70%**。这不是把模型做得不够大：当前标注把动作和休息混在同一类，且没有足够的困难负样本；更深的网络、强化学习或智能体只会更容易记住参与者与时间安排，而不会变得更可靠。

## 达标所需的下一轮数据

现有阶段标签不足以支撑可靠的三动作识别。下一轮必须保留同一顶帽、同一固定方式，并补齐：

1. 每个动作的每一轮用手机视频或明确的 LED/蜂鸣提示标记开始和结束；每人每类至少 6 次真实动作。
2. 每位参与者先检查后脑压力片是否有稳定变化，再采抗阻；无接触的样本不能被误标为抗阻。
3. 对每位参与者采集等量或更多的困难负样本：低头、点头、转头、耸肩、走路、看手机、喝水和正常坐姿调整。
4. 至少新增 10–15 位参与者；新增受试者仍保留为独立验证/最终测试，不能全放进训练集。

在数据达标前，演示版本可以运行本地状态机和采集/蓝牙链路，但不得宣称它已经通过 70% 的独立人群验证。
